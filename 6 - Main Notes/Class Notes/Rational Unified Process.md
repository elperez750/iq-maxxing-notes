## What is RUP
- RUP stands for Rational Unified Process
- It is a disciplined approach to assigning and managing tasks and responsibilities in a development organization. The goal with this process is to produce, within a predictable schedule and budget, high-quality software that meets the needs of its end users. 

###### RUP makes it easy for software projects of all sizes to work

The Rational Unified Process is represented with the use of four primary modeling elements, which are workers, activities, artifacts, and workflows.


A worker defines the behavior and responsibilities of an individual or a group of individuals.


###### So basically this is the team lead

An activity is something a worker does that provides a meaningful result in the context of the project


###### So like working on a component for an app?


An artifact is a work product of the process


The core process workflows are grouped into six engineering workflows: [[Business Modeling]], [[Requirements]], [[Analysis and Design]], [[Implementation]], [[Test]], and [[Deployment]].

### Workers

In RUP, a worker can be thought of as a hat, meaning that one person may have many hats or multiple roles

Some examples:
- System analyst - a person acting as system analyst leads and coordinates requirements elicitation and use-case modelling by outlining the systems and delimiting the system.

- Designer - a person acting as a designer defines the responsibilities, operations, attributes, and relationships of one or more classes.

- Test Designer - a person acting as a test designer is responsible for the planning, design, implementation and evaluation of test.

Workers are not individuals. They explain that an individual should conduct itself in the business and the responsibilities of each individual.

###### So to me, the worker seems like a role at a company, like System Analyst or Designer. I'm sure a Software Engineer could be included in this, as they are responsible for planning and designing.

### Activities

An activity is basically an act or duty taken by a member of the team to further the project

Some examples:

- Plan an iteration: performed by the worker: Project Manager

- Find use cases and actors: performed by the Worker: System Analyst

### Artifact

An artifact is information that is produced and modified or used by a process.

###### So would this be like an app? Or maybe some charts? Both of those are produced by teams.


Some examples:
- A model, such as the use-case model or the design model

###### This can then be used to design the actual product, so this related to the "used by a process" detail.


- Source code
- Executables
- A document, such as a business case or software architecture document.

### Workflows.

Basically this is just a sequence of activities that producers a result of observable values.

RUP is organized to reach the goal using the following:

- Core workflows
- Workflow details
- Iteration plans


## Dynamic Structure: Iterative Development

### The sequential process

The problem is that the [[Waterfall Model]] is very rigid and does not allow for changes throughout the project.

RUP breaks down the lifecycle of a large project into a succession of small waterfall projects.



![[Pasted image 20260403181435.png]]


### Four process phases
a development cycle is divided into a sequence of four phases that partition with help of milestones the sequence of iterations.

![[Pasted image 20260403181940.png]]


The four phases are:
- Inception Phase - This is when the initial plan for the project is developed. The team tries to understand business needs and how the project will help achieve business goals.

- Elaboration Phase - This is where the use cases for the project are developed. This is the step where the teams are organized, resources are allocated, and real specifications are agreed upon.

- Construction Phase - This is where the product goes from a mere idea to an actual thing that users can potentially use. 

- Transition Phase - This is where the project is handed over to the stakeholders. Things such as manuals, keys, and passwords are handed over, therefore concluding the project lifecycle.
